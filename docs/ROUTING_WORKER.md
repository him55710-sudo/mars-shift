# Background mission calculation

The browser's shared mission store delegates the existing constrained round-trip solver to a dedicated module worker. This changes scheduling and lifecycle, not the numerical route objective. The science/return-map worker stays separate. No new package or remote compute service is required.

The store holds the draft, last calculated inputs, last completed route reports, revision and frozen pre-event route. An explicit Calculate request snapshots the draft and starts a worker. Starting a newer request terminates the old worker. Request IDs also reject delayed or duplicate replies, including error callbacks. Completion replaces only the calculated result; edits and route-mode changes made during calculation remain in the latest draft. A mismatch still requires explicit calculation.

An exclusion freezes the current path and its invalidated cells before requesting a replacement. Pending calculations, failed calculations and unadopted replacements pause walking. Worker failure preserves previous paths as previous results and enables retry. It does not silently block the rendering thread with a synchronous fallback. Reset and terrain replacement cancel obsolete work; saved drafts preserve unapplied edits across reload.

The CLI/test path uses the same synchronous solver for reproducible numerical reports. Seven delayed-worker tests exercise the asynchronous browser contract. Actual Chrome calculation completed on the NOAH region with the displayed route revision updated; map controls remain available during the pending state. Two observed development timings were 1,034.9 and 1,300.4 ms. These are worker computation times, not end-to-end latency, GPU usage or FPS. Source cloning, renderer work and concurrent science computation can still consume resources. No zero-lag guarantee is made.

The production service worker includes both module-worker bundles and the new region's data and optical tiles. An installed cache must be complete before the UI claims offline readiness. New versions wait for existing clients to close, avoiding a forced mid-mission reload. Verified on the production build at localhost:4173: after cache readiness, the task preview server was stopped, the page reloaded, the NOAH terrain and return-feasibility layer rendered, and an explicit mission recalculation completed at revision 1 (1,469.6 ms worker time). There were no captured console errors. This verifies the local cached app; global remote basemaps and unrequested rover panoramas remain network-dependent.

`pnpm test` covers numerical routes and the delayed transport lifecycle. `node scripts/run_noah_analysis.mjs` records default routes, simulated invalidation, return-feasible areas, source identities and clearly separated single-run CLI timings in `public/data/noah/integration-results.json`.
