# MARS SHIFT v10 — 관측 지형 XR 통합 및 대피 연구 과정 검토

작성일: 2026-11-15. 기존 v7/v8/v9 실험 결과를 보존하고 별도 분기에서 작성했다.

**판정: 계산 엔진의 검증과 조건부 비교 실험은 갖췄지만, 실제 화성 먼지악마 대피 성능을 검증했다고 할 단계는 아니다.** 이번 변경은 사진과 같은 관측 Navcam 렌더러를 기본 XR에 통합하고, 자원 여유가 줄어든 상황에서 고정된 계획 시간 때문에 발생하던 경로 거부를 줄였다. 먼지악마 회피 성능이 크게 좋아졌다는 결과는 나오지 않았다.

## 1. 사진과 다른 화면이 나온 이유와 수정

기존 `/hazards` 기본 화면은 궤도 DEM 기반 비교 실험 화면이었다. 사용자가 보낸 사진은 Perseverance Sol 477 / Drive 1004의 Navcam 영상으로 텍스처를 입힌 관측 지형 화면이다. 두 화면은 지형 자료, 해상도, 카메라와 HUD가 달랐다.

새 기본 화면은 기존 `RoverScene`과 보정된 Navcam 타일을 재사용한다. 1인칭 시야, 작은 방향계, 지면을 따르는 민트색 경로, 관측 범위 미니맵, Terrain / Visor / Route / Layers 조작을 연결했다. 확대·축소와 시점 회전도 유지한다. 경로는 계산된 좌표를 그대로 표시하며 보기 좋게 만들기 위해 장애물을 가로질러 매끈하게 바꾸지 않는다.

Visor와 Route는 동일한 `XRNavigationFrame`을 사용한다. 모션 추정·경로 계산은 worker에서 수행하고, 관측이 도착하면 2초 제어 주기로 갱신한다. 경로와 소용돌이 경계는 같은 지형 좌표계를 쓴다. 접촉이 예측되면 HUD에 이를 표시한다. HOLD 중에는 이동 화살표를 숨긴다.

관측되지 않은 메쉬의 구멍과 불연속을 가상 평지로 채우지 않았다. 그곳은 이동 가능한 지형으로 취급하지 않는다. Navcam의 세밀한 시각적 형상이 모두 이동 그래프의 해상도로 표현되는 것도 아니다. 영상 해상도와 보행 가능한 표면 추정의 정확도는 별도 문제다. 이 지점에서 실제 먼지악마가 관측됐다는 뜻도 아니다.

현재 엔진은 유한한 후보 경로 중 예상 접촉시간과 불확실성 노출을 비교한다. 반대 방향, 옆 방향, 우회, 정지가 상황별로 다를 수 있다. **알려진 모든 예측 모델 중 최고**, **항상 탈출**, **전역 최적 경로**는 입증하지 않았다. 근거리에서 늦게 감지되면 물리적으로 피할 수 없는 조건도 포함한다.

## 4. 이번에 확인하고 수정한 병목

기존 엔진은 매번 48초 경로 전체가 복귀 예비 자원까지 만족해야 했다. 이미 출발점에 도달해 있고 다음 2초 실행은 가능한데 남은 가용 시간보다 48초가 길면 경로를 거부할 수 있었다. 이는 실제 귀환 실패와 다른 **계획 거부**였다.

새 버전은 공통 계획 시간을 `min(48초, 남은 가용 시간 − 현재 지점에서의 귀환 시간)`의 그래프 시간 격자로 제한한다. 실행 구간 2초는 유지하고 모든 후보 정점에서 기존 자원 조건을 다시 확인한다. 원래의 귀환 우선순위 기준은 유지했다. 세 비교 모델에 동일하게 적용했다. 이전 엔진·결과를 수정하지 않았다.

추가한 대피 시간 진단은 **현재 위치에 머무를 경우 물리 반경 + 1 m 경계가 처음 도달하는 시간**이다. 중심 도착 시간이 아니다. 정지 구간을 이동 완료 시간으로 세지 않는다. 경로 끝에 경계보다 먼저 도착해도 이동 도중 접촉할 수 있으므로 전체 경로의 연속 접촉 검사를 함께 유지한다. 이 반례를 회귀 테스트에 넣었다. UI의 BOUNDARY ARRIVAL은 이 조건부 시간이며 실제 관측 경고시간은 아니다.

**세 모델 모두 위의 공학적 통과 조건을 만족했다. 접촉시간이나 무접촉률 개선은 없었다.** 새 통합 모델의 평균 접촉시간은 이 조건 집합에서 정적 모델보다 약 15.8%, Nominal보다 약 2.0% 낮다. 이는 기존 정책 간의 차이이며 이번 수정이 만든 이득이 아니다. 독립적인 실제 사건에 대한 통계적 우월성이나 큰 성능 격차를 입증하지 않는다.

수정 후 평균 최소 이격거리는 Static 0.585 m, Nominal 0.902 m, MARS SHIFT 1.042 m이다. 음수는 모델 경계 내부 진입이며 통합 모델의 최악 사례는 −10.146 m로 여전히 접촉한다. 통합 모델 계획 계산 p95는 이 컴퓨터에서 약 3.25 ms였지만, 브라우저·worker 통신·센서 지연을 포함한 종단 지연이 아니고 실행 중 다른 작업도 있었으므로 운용 장비 성능 보장으로 해석하지 않는다.

남은 통합 모델 거부 사례는 `horizon-012/014/024/026`이다. 48초 자체가 부족해지는 말기 상황과 달리, 임무 목적지를 향한 후보가 복귀 예산을 만족하지 못하는 상황이 귀환 전환 기준보다 먼저 발생한다. Nominal에는 `horizon-002`도 있다. 이를 보고 결과를 다시 맞추도록 같은 평가 세트를 재조정하지 않았다. 다음 변경에서는 **목적지 후보가 자원상 부적합할 때 귀환·대기 후보도 비교하는 정책**을 개발용 집합에서 구현하고, 별도의 동결 집합으로 확인해야 한다. 현재 남은 거부가 모두 '피할 경로가 물리적으로 없다'는 증거는 아니다.

기존의 7,200조건과 이번 36조건은 독립적인 실제 관측 수가 아니다. 실제 관측 추가 확보가 없으므로 이를 관측 기반 백테스트가 늘었다고 보고하지 않는다.

## 6. 다음 검증의 우선순위와 채택 조건

1. **측정 가능한 관측 입력 확보:** 시간 보정된 영상·거리 또는 다중 관측 지점으로 중심·직경을 미터 단위로 추정하고, 각 값의 불확실성과 결측을 저장한다. 풍속 시계열만으로 독립 소용돌이 중심 궤적의 정답을 대신하지 않는다.
2. **사건 단위 분할:** 같은 사건의 연속 프레임을 개발/검증에 나누지 않는다. 사건 또는 관측일을 묶어 미리 분할하고, 자료가 적으면 과도한 일반화 대신 사례별 결과를 보고한다.
3. **예측 먼저 평가:** 1/3/5/10/20초 선행 시간별 중심 오차, 방향 오차, 직경 오차, 경계 포함률과 센서 누락을 비교한다. 단순 등속·평활 등속·가속/전환 모형을 같은 입력으로 비교한다. 미래 관측을 사용하는 평활기는 운용 예측에 섞지 않는다.
4. **그 다음 폐루프 대피:** 모든 모델에 같은 실제 지형·속도·지연·자원 조건을 적용한다. 완전정보는 도달 가능한 성능의 참고로 분리한다. 근거리 발생·빠른 횡단·급회전·좁은 지형·센서 결측·예산 부족을 포함한다. 접촉시간과 최악 이격거리, 귀환, 실행 가능한 거부/정지 비율을 함께 보고한다.
5. **거부와 실패를 분리:** 센서 부족, 예측 오류, 계산 제한, 자원 부적합, 물리적 탈출 불가능을 구분한다. 기준선 대비 평균 이득만으로 긴급 상황에서의 큰 손실을 숨기지 않는다.
6. **채택:** 동결된 새 사건·조건에서 일관된 개선이 확인될 때만 XR 기본 정책을 바꾼다. 신뢰 구간은 사건 단위로 산출하고, 합성 변형 수를 실제 사건 수로 세지 않는다. 실패한 후보도 보존한다.

이번 범위는 대피 경로와 노출 최소화이며 우주복 손상이나 헤드셋 안전성 평가를 추가하지 않았다. 현재 화면은 실제 관측 지형에서 계산 과정을 보여 주는 연구용 리허설이다.

## 7. 재현

`node scripts/run_evacuation_v10.mjs freeze`와 `... evaluate`는 기존 파일을 덮어쓰지 않는다. 현재 배포된 파일은 위 동결 실행의 기록이다. 재실행은 복사한 작업 공간의 별도 출력 경로를 사용한다. 프로토콜은 엔진 원본의 SHA-256을 기록하고 평가 전에 확인한다. 기존 v8/v9 기록은 그대로 남아 있다. TypeScript 검사, 자동 테스트, production build, 모바일/데스크톱 실제 브라우저 검사를 별도로 수행했다.
